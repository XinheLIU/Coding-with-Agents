# 第三章：成为高级用户

Last updated: 2026-11-10

> *使用编程智能体与精通它之间的差异，就像会开车与调度一支车队之间的差异。*

[第二章](../02-anatomy/README.md)把这台机器拆开了：智能体如何工作、该给多大自由度，以及 Claude Code 的内存、扩展与集成各层如何组装在一起。本章要把这套解剖学变成工程实践——正是这些系统和纪律，把从 AI 获得 2 倍效能的开发者与获得 10 倍效能的开发者区分开来。

本层包含七章。目前五章可读（规格编码、产品业务与工程底座、智能体前端开发、代码库记忆为草稿），另两章仅有占位提纲，尚未加入目录。进度见仓库根目录的
[`ROADMAP.md`](../../../ROADMAP.md)。

1. **编排层（Orchestration Layer）（占位）** — 如何设计位于单个智能体之上的那一层：在会话、智能体和工作流之间调度工作，决定哪些任务自主运行、哪些交互执行，并把子智能体、Hooks 和 Skill 组合成可复用的流水线，而不是一次性的技巧。

2. **工程框架（Engineering Frameworks）（占位）** — 让智能体辅助开发变得可靠的可复用结构：项目脚手架、验证闭环、任务拆解模板，以及围绕智能体原生工程正在形成的各种框架。

3. **[规格编码（Spec Coding）](spec-coding.md)（草稿）** — 规格优先的开发方式：把想法交付成产品的六步流程（Spec 文档、设计标准、架构施工图、项目管理与长期记忆、迭代验收、版本管理）；六维需求体系与交付闭环仍在撰写中。

4. **[产品、业务与工程底座：智能体开发的三层分工](product-business-engineering.md)（草稿）** — Agentic Coding 是内外双循环：智能体并行执行内循环，人在外循环定意图、拍板、修改环境，而整个代码库就是 Harness。三层分工的实质是给智能体供给 context 与 constraint；隐性知识的挖掘决定内循环的上限；配约束强度阶梯和两个设计——外循环的工程组件初始化（含参考切片），以及改进循环中证据驱动的重构与组件提炼。

5. **[智能体前端开发：从生成、品味到验证](agentic-frontend.md)（草稿）** — 为什么前端对智能体比后端更难（缺少可验证的信号）；前端 AI 的瓶颈如何从生成迁移到品味、再到验证，以及 Google（Stitch → DESIGN.md → Antigravity 管线）、OpenAI（模型审美 + Codex 插件与「概念图即规格」）、Anthropic（Skill + harness）三条路线为何殊途同归；配套做法：收窄生成空间、把品味写进 DESIGN.md 与 Skill、验证阶梯与自主性调节。

6. **[代码库记忆：只存 Why](repo-memory.md)（草稿）** — 从 Harness Memory 的整体视角重新设计智能体的记忆：六类记忆（结构、约束、程序、派生、声明、状态）各自如何作用于智能体，哪些约束蕴含在代码之内、哪些必须从人脑显性化；What 交给代码，How 交给可执行的控制，手写只存 Why；给出十一条设计原则、三问过滤器、给人看的 presenter 层，以及规格从施工图到决策记录的生命周期。

7. **[接手存量代码库](legacy-codebases.md)** — 让智能体面对大型存量系统的高级用户策略：存量系统中的三种债务、理解—约束—验证三层控制，以及通过「Characterization Test → Seam → 增量重构」保持智能体驱动的改动可逆。
